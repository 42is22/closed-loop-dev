# 독립 검증 (closed-loop-dev)

구현 세션이 끝나고 사용자가 커밋을 알리면, **다른 세션**이 그 커밋을 검증한다. 목적은 구현 세션이 원리상 못 보는 결함을 찾는 것이다.
절차의 상세는 스킬 `cld-verify` 다. 이 규칙은 빠뜨리면 안 되는 것만 적는다.

## 무엇을 검증하나

- **작업 트리가 아니라 커밋을 검증한다.** 커밋 해시를 받으면 `git log` 로 그 뒤 커밋을 모두 찾는다. 사용자가 «다 읽어봐» 라고 하면 그 범위 전부다.
- **깨끗한 트리에서 돈다.** `python .cld/harness/cld.py tree <rev> --out <스크래치>` — 추적하지 않는 파일(키 · 캐시 · 로컬 설정)이 결과를 가리지 않게 한다.
- **게이트를 다시 돈다.** 구현 세션의 숫자를 옮겨 적지 않는다. 기대 수(시험 개수 · 불일치 0 등)는 인수인계 · CHANGELOG 의 주장과 대 본다.
- **빌드 · 배포에 닿는 커밋은 깨끗한 트리로 풀빌드하고 설치본(산출물)으로 시험한다.** 평문 게이트는 난독화 · 패키징 · 설치 경로가 깨뜨린 것을 원리상 못 본다.
- **값 불변을 주장하는 커밋은 흔든 입력으로 전후 트리를 대 본다.** 기본값이 우연히 같아 가려지는 결함(0.0 · 빈 값)이 있다.

## 어떻게 나누나

- **읽기 전용 에이전트 넷 ~ 여섯, 관점 하나씩**(에이전트 `cld-reviewer`). 관점은 `cld.py verify scope <base> <head>` 가 바뀐 파일에서 제안한다.
  꼭 둘 관점: «게이트가 타지 않는 입구» · 값 불변 주장(해당하면). 무거운 발견은 반증 담당(`cld-refuter`)이나 메인이 코드로 다시 확인한다.
- 에이전트는 세션 프롬프트를 못 본다. 에이전트 프롬프트마다 공통 규칙(저장소 수정 금지 · git 읽기 전용 · 무거운 프로세스 금지 · 사본 트리 · 근거)을 넣는다 — `verify scope` 가 문장을 낸다.
- 메인 루프가 게이트 · 빌드 · 기록을 한다. 게이트와 에이전트는 동시에 돌려도 되지만, 서로 같은 자원(포트 · 폴더 · 설치본)을 쓰지 않게 한다.

## 무엇을 남기나

- **발견은 심각도로 가른다.** 🔴 운용 · 안전 · 데이터 손실 / 🟡 실제 결함이나 도달 조건이 좁다 / ⚪ 문서 · 표기 · 시험 빈틈. 근거(파일:줄 · 재현)가 없는 발견은 적지 않는다.
- 기록 자리: 인수인계 그 항목(머리 · 믿지 말 것 · «N. 독립 검증» 이월 목록) · CHANGELOG 그 항목의 «독립 검증» 한 줄 · 마스터 플랜 상태 칸 · 필요하면 과제. 문서 기록은 `cld.py patch`(정확한 자리 · 줄 끝 보존)로 한다.
- **문서 오류는 검증 세션이 바로 고친다.** 코드 결함은 고치지 않는다 — 이월 목록에 싣고 다음 커밋이 고친다.
- 끝에 사용자에게 준다: 결론 먼저 · 무엇을 돌렸나(표) · 무엇을 찾았나 · 정할 것 · 커밋 명령(메시지 파일 경로).
