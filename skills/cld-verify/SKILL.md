# 독립 검증

구현 세션과 **다른 세션**이 한다. 구현 세션의 숫자를 옮겨 적지 않고 다시 잰다. 코드는 고치지 않는다 — 결함은 이월 목록에 싣는다. 문서의 사실 오류는 바로 고친다.

## 0. 범위 잡기

1. `git status --short`(작업 트리가 깨끗한가 — 아니면 사용자에게 알린다) · `git --no-pager log --oneline -n 15`.
2. 사용자가 해시 하나를 줬으면 그 커밋까지, «다 읽어봐» 면 직전 검증 커밋 뒤의 **모든** 커밋이 범위다. 문서 커밋 · 해시 커밋도 포함한다.
3. `python .cld/harness/cld.py verify scope <base> <head> --out <스크래치>/scope.md` — 커밋 · 바뀐 파일 · 제안 관점 · 에이전트 공통 규칙.
4. 인수인계의 그 항목(구현 세션이 넣은 것)과 CHANGELOG 항목을 읽는다. 구현 세션이 **주장한 것**(게이트 수 · 불변 · 한계)을 목록으로 만든다 — 검증은 이 주장을 하나씩 대는 일이다.

스크래치는 저장소 밖(세션 스크래치 폴더)에 `verify_<head>/` 로 둔다.

## 1. 긴 것부터 띄운다(백그라운드)

- **게이트**: `python .cld/harness/cld.py gates run --out <스크래치>/gates` — 저장소 HEAD 가 검증 대상과 같고 작업 트리가 깨끗하면 저장소에서 돌려도 된다. 아니면 깨끗한 트리에서.
- **깨끗한 트리**: `python .cld/harness/cld.py tree <head> --out <스크래치>/tree` (Windows 긴 경로면 `--subst T:`).
- **풀빌드 · 산출물 시험**(빌드 · 패키징 · 설치 · 난독화에 닿는 커밋만): 깨끗한 트리에서 빌드하고, 그 산출물로 프로젝트의 산출물 시험을 돈다. 평문 게이트는 이 경로의 결함을 원리상 못 본다.
- 서로 자원(포트 · 폴더 · 설치본 · 드라이브 문자)이 겹치는 것은 순서로 잇는다. 기다림은 폴링하지 말고 끝나면 알림이 오게 건다.

## 2. 관점 에이전트(읽기 전용 · 넷 ~ 여섯 · 동시에)

- 에이전트 하나에 관점 하나. 에이전트 정의 `cld-reviewer` 를 쓴다(없으면 일반 에이전트 + 같은 규칙).
- 프롬프트마다: 대상 커밋 · 기준 커밋 · 먼저 읽을 것 · **볼 것 번호 목록(질문 형태)** · `verify scope` 의 공통 규칙 · 사본 트리 폴더 · 보고 형식(결론 먼저 · 심각도 · 파일:줄 · 재현).
- 꼭 둘 관점:
  - **게이트가 타지 않는 입구** — 스위치 · 설정 조각 · 도구 인자 · 설치 · 업데이트 · 롤백 경로.
  - **새로 거부 · 차단하는 조건**(기동 게이트 · 검증 규칙 추가 등)이 있으면 — 이미 운용 중인 대상(현장 · 사용자 데이터)이 새로 막히는가.
  - 보안 · 인증이 있으면 보안 관점, 화면이 있으면 프런트 · 계약 관점, 문서가 많이 바뀌었으면 문서 대조 관점.
- 에이전트는 시험 스크립트를 저장소에서 돌리지 않는다(메인이 돈다). 돌연변이 시험은 사본 트리에서 — «시험이 이 보장을 실제로 단언하는가».

## 3. 메인 루프가 직접 하는 것

- **값 불변 주장**: 흔든 입력(설정 값 · 경계 값을 서로 다른 값으로)으로 전후 트리의 결과 · 문맥을 대 본다. 기본값이 우연히 같아 가려지는 결함을 잡는다.
- **무거운 발견은 코드로 다시 확인**한다(에이전트 보고를 그대로 옮기지 않는다). 확인하지 못했으면 «그럴듯함(PLAUSIBLE)» 으로 적는다.
- 게이트 · 빌드 · 산출물 시험 결과를 주장 목록과 대 본다(수 · 불일치 0 · 시간).

## 4. 기록(문서만 · 한 번에)

`python .cld/harness/cld.py patch <스펙.json> --check` 로 자리를 대 본 뒤 적용한다(정확한 자리 · 줄 끝 보존 · 전부 또는 전무).

| 자리 | 무엇 |
|---|---|
| 인수인계 그 항목 | 머리 괄호(검증 날짜 · 결과) · «깨지기 쉬운 것» 새 함정 · «믿지 말 것» 틀린 주장 · «다음 사람에게» 끝 «N. 독립 검증 — 이월 목록의 SSOT» · 변경 이력 |
| CHANGELOG 그 항목 | «독립 검증(날짜)» 한 줄 — 게이트 · 빌드 · 🔴/🟡 요약 · 이월 위치 |
| 마스터 플랜 | Phase 행 상태 «완료(<커밋> · 독립 검증 날짜 — 결과)» |
| 과제 | 🔴 · 큰 🟡 는 과제로 떼거나 기존 과제에 사실로 |
| 세션 프롬프트 | 남은 단계 ✅ 줄 — «이번 세션» 은 사용자 결정 뒤 `cld-close` 가 다시 쓴다 |
| 현장 절차 SSOT | 운용자가 보는 문서(종료 코드 · 설치 절차)에 ⚠ 가 필요하면 |

그리고 `python .cld/harness/cld.py handover check`. 커밋 메시지 초안을 파일로 쓴다.

## 5. 사용자에게

순서: **결론 먼저**(🔴 수 · 게이트 통과 여부) → 무엇을 돌렸나(표) → 무엇을 찾았나(🔴 → 🟡 → ⚪ 한 줄 묶음) → 기록한 곳 → **정하실 것**(선택지 · 권고 · 근거) → 커밋 명령(`git add -u; git add <새 파일>; git commit -F "<메시지 파일>"`).

- 긴 작업 중에는 짧은 진행 메시지를 남긴다(무엇을 기다리는지).
- 사용자 결정을 받으면 `cld-close` 로 루프를 닫는다.
