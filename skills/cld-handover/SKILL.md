# 인수인계

인수인계는 세션 사이의 유일한 기억이다. 무엇을 했는지가 아니라 **무엇을 깨뜨리기 쉬운지**를 적는다.

## 항목 넣기(구현 세션)

```
python .cld/harness/cld.py handover new --phase <id> --title "<제목>"
```

표식(`<!-- cld:handover-insert -->`) 바로 아래 = 맨 위에 틀이 들어간다. 자리표시(`{{…}}`)를 모두 채운다. 같은 Phase 의 다음 커밋은 새 항목을 만들지 않고 그 항목을 고친다.

| 칸 | 적는 것 | 적지 않는 것 |
|---|---|---|
| 깨지기 쉬운 것 | 무엇 · 어떻게 깨지나 · 지키는 장치(시험 이름 — 없으면 «없음») | 잘 돌아가는 것 |
| 되돌리는 법 | 이 커밋만 되돌릴 때의 파일 · 재빌드 · 데이터 | 일반 git 사용법 |
| 믿지 말 것 | 어디(문서 · 주석 · 계획 행) · 무엇이 틀렸나 | 원래 맞는 것 |
| 다음 사람에게 | 번호 붙은 구체적 지시 · 게이트 결과 표 | 덕담 · «조심하라» |

- 빈 칸은 «없음». 한 쪽(설정 `handover.max_section_lines`)을 넘지 않는다. 넘으면 조사 · 측정 · 경위를 docs/RPT 로 보낸다.
- «완료했다 · 측정했다» 는 CHANGELOG 몫이다. 여기에는 다음 사람의 행동을 바꾸는 것만.
- 줄 번호 대신 이름(함수 · 절 제목 · 행의 첫 칸)으로 가리킨다. 줄 번호는 낡는다.

## 검사

```
python .cld/harness/cld.py handover check [--phase <id>]
```

네 칸의 유무 · 순서 · 빈 칸 · 남은 자리표시를 본다. 실패하면 exit 1. 길이는 경고만 한다.

## 검증 세션이 고칠 때

새 항목을 만들지 않는다. 구현 세션이 넣은 그 항목을 고친다(`python .cld/harness/cld.py patch <스펙.json>` — 정확한 자리 · 줄 끝 보존).

- 머리 괄호: «독립 검증 YYYY-MM-DD — 게이트 결과 · 🔴 N · 🟡 N — «N»».
- «깨지기 쉬운 것»: 검증이 찾은 함정 행을 더한다(«(독립 검증)» 표시).
- «믿지 말 것»: 구현 세션 문서 · 주석 · CHANGELOG 의 틀린 주장을 행으로. 원문은 고치지 않는다(이력). 문서의 단순 오류는 바로 고치고 그 사실을 적는다.
- «다음 사람에게» 끝: «**N. 독립 검증(날짜) — 이월 목록의 SSOT(고치는 자리: …).**» + 게이트 · 빌드 결과 한 문단 + ⓪ 물을 것 + ① ② … 🔴 · 🟡(고칠 자리 제안 포함) + ⚪ 한 묶음.
- 변경 이력 표에 한 줄.
