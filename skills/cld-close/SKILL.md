# 폐루프 닫기

검증 세션의 끝이자 다음 구현 세션의 시작 준비다. 문서만 고친다.

## 1. 사용자 결정 반영

- 결정은 **날짜와 함께** 마스터 플랜 §4 결정 기록에 적는다(무엇을 · 왜 · 버린 대안).
- 순서가 바뀌면 §2 Phase 표의 순번과 세션 프롬프트 «남은 Phase» 를 함께 고친다. 이름은 바꾸지 않는다.
- 이월을 어디서 고칠지 정해졌으면: 그 커밋 단계의 Phase 절 «이번 세션» 에 이월 번호를 싣는다. 새 단계를 만들었으면(사용자가 승인한 경우만) 마스터 플랜 표에 행을 더하고 이유 한 문장을 적는다.
- 과제 상태(인덱스 포함) · 과제 문서의 «승인 필요» · «트리거» 를 결정대로 고친다.
- 인수인계 이월 목록의 ⓪ 물을 것을 «🟢 결정(날짜): …» 로 바꾼다.

## 2. 다음 «이번 세션» 준비

- 다음 Phase 절의 «■ 이번 세션» 을 다시 쓴다: ✅ 줄(끝난 것 한 줄) · 권고 모드와 근거 · ⓪ 물을 것 · 이월 · 할 일 · 하지 않는 것. 끝난 단계의 상세는 걷는다.
- 새 코드가 지켜야 할 임시 금지(예: 다음 커밋이 고치기 전까지 피할 모양)가 있으면 «이번 세션» 과 인수인계 «다음 사람에게» 에 함께 적는다.
- `python .cld/harness/cld.py prompt build <다음 id> --out <스크래치>/p.txt` 로 조립이 되는지 본다(머리 · 낱말 · 블록 검사).

## 3. 사용자에게

- 반영한 곳 목록과 커밋 명령(메시지 파일 갱신).
- 제가 대신 정한 것이 있으면(예: 합칠 자리) 그 이유 한 문장과 «바꾸려면 말씀해 주세요».
- 다음 프롬프트는 요청을 받으면 `cld-prompt` 로 준다(«대상: …» 로 시작 · 모드 권고 먼저 · 복사용 전문).
