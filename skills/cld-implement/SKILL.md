# 구현 세션

붙여 넣은 프롬프트가 지시의 SSOT 다. 이 스킬은 모든 구현 세션에 공통인 규율이다.

## 1. 시작

1. 인수인계(`.cld/config.toml` docs.handover)를 먼저 읽는다. «믿지 말 것» 과 «다음 사람에게» 는 전부.
2. 규칙(`.claude/rules/cld-*.md` 와 프로젝트 규칙)과 마스터 플랜의 이 Phase 행 · 결정 기록을 읽는다.
3. 프롬프트의 «⓪ 물을 것» 을 **착수 전에** 묻는다(선택지 · 권고 · 근거 한 줄). 답을 받기 전에 그 결정에 걸린 코드를 쓰지 않는다.
4. 프롬프트에 없는 설계가 필요하면 짧은 초안(한 쪽 — 커밋 나눔 · 인터페이스)을 내고 승인받는다.

## 2. 구현

- 이번 Phase 의 범위만 한다. 부수적 개선을 더하지 않는다. 다음 Phase 의 일은 인수인계 «다음 사람에게» 에 적는다.
- 값 불변 커밋에서 게이트가 차이를 내면 **멈추고 원인을 적는다.** 기준선을 다시 뜨지 않는다.
- 🔴 · 🟡 모드면 프롬프트 끝의 «다중 에이전트 운용» 을 따른다. 에이전트 프롬프트마다 공통 규칙을 넣는다(`cld.py verify scope <base> HEAD` 가 문장을 낸다).
- 게이트: `python .cld/harness/cld.py gates run --out <저장소 밖 스크래치>`. 게이트가 못 보는 경로(설치 · 배포 · 화면)는 이 커밋의 전용 시험을 만든다.
- 사용자가 돌려야 하는 긴 시험(실장비 · 설치 프로그램)은 넘기기 전에 판정이 공허하게 통과하는 조건이 없는지 점검한다.

## 3. 끝낼 때 (한 변경에 전부)

1. **인수인계**: `python .cld/harness/cld.py handover new --phase <id> --title "<제목>"` → 네 칸 채우기 → `handover check` 가 OK.
   - 깨지기 쉬운 것 · 되돌리는 법 · 믿지 말 것 · 다음 사람에게. 빈 칸은 «없음». 한 쪽을 넘지 않는다.
   - «다음 사람에게» 끝에 게이트 결과 표를 둔다(게이트 · 결과). 워크플로를 돌렸으면 찾은 결함 수 · 반증된 수를 한 줄.
2. **마스터 플랜**: 이 Phase 행의 «상태» 를 `진행` 또는 `완료(구현 — 검증 전)` 로. 결정이 생겼으면 §4 에 날짜와 함께.
3. **CHANGELOG** `[Unreleased]`: 무엇 · 왜(한두 문장) · 운용 영향 · 롤백 · 게이트 한 줄. 측정 표 · 조사 경위는 docs/RPT 로.
4. **과제**: 새로 드러난 부채는 tasks/ 에 과제로(인덱스와 같은 변경에서). 겹치는 과제는 그 문서를 고친다.
5. **커밋 메시지 초안**을 파일로 쓰고(스크래치), 사용자에게 준다: 변경 파일 목록 · 게이트 결과 · 명령(`git add …; git commit -F "<파일>"`). 커밋은 사용자가 한다.
6. 끝내지 못했으면 인수인계에 멈춘 자리와 남은 일을 적는다.

다음 프롬프트를 만들지 않는다. 사용자가 커밋을 알리면 **다른 세션**이 독립 검증을 한다.
